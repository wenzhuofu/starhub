# 整理：归类与编译

知识库遵循 LLM Wiki 约定：`AGENTS.md` 是 schema，`wiki/index.md` 是目录，`wiki/log.md` 是日志，每个主题是 `wiki/<主题路径>.md`。目录和日志由命令维护，你只写笔记正文。`wiki/insights/` 是用户自己写的页面，只读，不改。

新收藏进来后只做两件事：

1. **归类**：每条收藏标上主题、类型、实体和场景。
2. **编译**：有新成员的主题，增量改写它的笔记。

原则是先便宜后昂贵：归类只看标题级的信息，正文由同步时慢慢补全，编译时再用。

## 0. 主题树（只在第一次，或者「待定」积攒太多时）

1. 运行 `starhub taxonomy propose`。它会按平台和收藏夹分组，列出全部标题。
2. 提一版主题树：
   - 一级 5 到 12 个，按用户真实的生活和工作领域来分，比如旅行、做饭、AI、设计、职场；
   - 每个一级下最多 8 个二级；
   - 起名用用户自己会说的词，2 到 6 个字。
3. 把这版树给用户看，按他的意见改好，再运行 `starhub taxonomy apply <文件>`。没得到确认之前，不要应用。

之后需要新主题时，用 `starhub taxonomy add <路径>`。新主题只能挂在已有节点下面。

## 1. 归类

1. 运行 `starhub classify`。它给出一批待归类的收藏（每行一条，只有标题级信息），以及当前的词表。
2. 每条写一行 JSON，全部存成一个 JSONL 文件，交给 `starhub label <文件>`。字段：
   - `topic`：词表里已有的路径。优先选二级主题，只有确实不属于任何二级时才挂一级。实在归不进去就写 `待定`，不要硬塞。
   - `kind`：从固定的类型里选一个。面经、经验贴用「经验」；纯消遣的片段（搞笑、直播切片）用「娱乐」。
   - `entities`：最多 3 个，写成 `类型:名字`，用规范的名字，比如「地点:杭州」，不要写「杭州西湖边」。
   - `scene`：最多 20 字，写用户以后会在什么情境下想起它，比如「去杭州玩两天」。
3. `label` 拒收的行，按它给的原因改好，再交一次。
4. 重复以上，直到 `classify` 不再输出。

这一步只看标题和简介，不要读正文。看不出主题的就放进 `待定`。

## 2. 编译

先读 `references/compile.md`：写给谁看、怎么写、不要写什么，都在那里。然后：

1. 运行 `starhub compile`，列出待编译的主题。要重写全部主题时，用 `starhub compile --all`。
2. 逐个主题运行 `starhub compile <主题>`，拿到成员和摘录，写一篇完整的笔记，再用 `starhub note <主题> <文件>` 保存。
3. `note` 拒收时，按提示改好再交。
4. 在 `related` 里写 1 到 3 个确实有关的主题。收藏里推荐的 GitHub 项目写进 `tools`，它们会进工具架的待分拣。

## 3. 收尾

运行 `starhub lint`。断链、index 缺项这类机械问题直接修；其他问题列给用户。

## 归类示例

| | 好 | 不好 |
|---|---|---|
| scene | 去杭州玩两天 | 旅游 |
| entities | 地点:杭州、地点:龙井村 | 杭州西湖边 |
